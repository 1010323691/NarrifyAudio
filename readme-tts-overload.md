# 批量音频合成启动减压：实现与验收

## 目标与边界

10 个用户同时提交，每人 500 章、每章 100 段，共 5000 章 / 50 万段。API 只接收章节引用和制作参数；语音段在 Worker 中按受控批次准备，不在请求中展开。默认同一主机只执行一个存活的 TTS 批次，其余持久化排队。这个保守策略涵盖准备和模型执行全过程。

本次验证覆盖真实 HTTP、PostgreSQL、鉴权、任务提交、SSE、控制接口及真实准备逻辑；在 TTS 子进程边界用桩替代模型。50 万段是队列承载量，不能解释为 50 万段同时进入模型。真实模型吞吐、显存峰值和 Windows 部署仍需在目标硬件验收。

## 原因与改造对应

| 原先放大压力的位置 | 当前处理 |
| --- | --- |
| 500 章逐章提交、复制完整配置、生成队列消息 | 一个原子事务，配置只保存一次，任务和事件按 100 条批量写入，一次唤醒 |
| Worker 逐章领取、额度预留、阶段更新、续租 | 批量领取、批量额度预留和事件更新、批量续租；准备期控制状态短缓存 |
| 重复解析配置、重复计算角色参数和签名 | 同批共享角色缓存，清单迁移复用已经读取的配置和参数 |
| 无上限读取输入和历史清单，整批 JSON 生成多个副本 | 文件、总字节、段数和内存预算；JSON 流式写入临时文件 |
| 多用户同时准备与加载模型 | 全局存活批次门禁，可用内存滞回门禁，既有 GPU 调度继续生效 |
| SSE 重放完整历史 / 大结果，长期占用数据库连接 | 摘要状态持久化，分块快照，TTS 结果只推送计数，日志按需分页；鉴权后释放连接 |
| 大量事件导致前端反复遍历列表 | 快照每 100 条一块，按 ID 定位，批量追加，账号切换丢弃未完成快照 |
| 点击后等待期间再次提交、刷新后遗失结果 | 同步锁定按钮，持久化幂等键，服务端原子防重，按原键确认或重试 |

## 默认限额

| 层级 | 上限 / 行为 |
| --- | --- |
| 提交入口 | 每进程同时处理 2 个提交；包含执行者在内最多接纳 32 个请求；等待超过 10 秒返回 429 |
| 请求体 | 实际接收最多 1 MiB，读取期限 10 秒；适用于旧 TTS 接口和通用任务提交接口 |
| 章节 | 单次最多 500 章，单用户最多 1000 个在途章节，全局最多 10000 个在途章节；通用多章任务按章节计数 |
| 冲突 | 同一项目、同一音频包的合成和重置互斥；原名和 `_checked` 名统一识别；冲突返回 409 |
| 幂等 | 用户 + 幂等键唯一；请求相同返回原回执，内容不同返回 409；即使完成或额度已耗尽也可查询原回执 |
| 准备 | 单文件最多 8 MiB；输入合计 64 MiB；清单合计 64 MiB；单批最多 50000 段 |
| 内存 | 准备 RSS 增长预算 1 GiB，预留 64 MiB 检查余量；可用内存低于 1 GiB 中止准备 |
| 启动门禁 | 可用内存低于 2 GiB 暂停新批次；恢复到 3 GiB 后继续；Linux 同时考虑 cgroup 限额 |
| 数据库 | API 业务池 16 + 锁池 8；每个 Worker 业务池 3 + 锁池 1；默认 overflow=0、等待 3 秒；1 API + 2 Worker 最多 32 个连接 |
| SSE / 日志 | 每用户最多 3 条任务 SSE；摘要快照每块 100 条；日志每页 100 条，前端最多保留 1000 条 |
| 状态查询 | 每个请求最多 100 个名称；前端自动分块串行查询 |
| 缓存 | 角色读取 64 MiB/2048 项，缺失角色汇总 8 MiB/32 项，状态缓存 32 MiB/512 项；按保留字节和项数双重淘汰 |

超出输入预算会以明确错误结束任务，保留已经发布的音频；排队容量满时返回 429 和 Retry-After。数据库连接超时返回 503。运行中的任务仍使用既有取消、暂停、租约及发布栅栏，批量优化没有绕过这些检查。

## 前端交互

点击立即显示“正在提交合成任务…”并禁用续合 / 重合按钮；超过 5 秒改为“服务器正在处理提交，请稍候…”。网络错误或 5xx 显示“正在确认提交结果…”，不会生成新的幂等键。页面刷新后可恢复；恢复轮询按 1、2、4、8、10 秒退避，隐藏或离开页面暂停。

重合采用同一操作中的两个固定键（重置和合成）；重置成功状态持久化，响应丢失不会再次删除音频。账号 / 项目切换使旧响应失效，提交绑定原项目。任务全部终态后释放锁；即使章节已经移出 SSE 最近窗口，也能通过完整回执状态确认。

准备、解析输入、加载模型、模型就绪是阶段提示，不作为已合成段数。批次页面保留多个章节合并后的有限实时日志；单任务完整历史按需分页查询。

## 部署、停止新任务和回退

新增迁移 `0023_batch_submission`：批次回执表、共享配置引用、事件序号、摘要状态和章节容量计数。升级应先备份数据库，停止 API 和 Worker，运行 `alembic upgrade head`，再同时启动新版 API、Worker 和前端。不能让旧 Worker 执行引用共享配置的新任务。本次代码实现没有迁移或重启正在运行的应用服务。

应急环境变量：

- `NARRIFY_TTS_SUBMISSIONS_ENABLED=false`：拒绝新提交，原幂等键仍返回已提交回执。
- `NARRIFY_TTS_PREPARATION_ENABLED=false`：暂停领取新 TTS 批次，已运行任务继续受既有控制机制管理。

这些设置启动时读取，需要重启相应进程；不会自动终止正在合成的子进程。数据库池也可通过既有 `NARRIFY_API_DB_*` / `NARRIFY_WORKER_DB_*` 参数调整，但总连接预算必须按进程数重新计算。

降级前先停新提交并排空或取消所有新版批次任务，再停 API / Worker。迁移降级会拒绝仍有在途批次的情况；成功降级时将共享配置还原到历史任务 payload，以便旧版重试读取。降级会删除回执和摘要结构，需要同步处理浏览器尚未确认的提交状态，不能在有不确定提交的情况下直接切回旧前端。

阶段指标 `submission`、`member_claim`、`preparation`、`model_load` 保留最近 2000 个样本，提供 P95；指标属于当前进程，API 的性能接口不会自动汇总其他 Worker 的样本。生产跨进程统计需要另行接入指标采集。
