# 管理控制台 UI / UX 重构

## 现状分析与范围

原后台使用 Vue 3、TypeScript、Pinia、Tailwind、Lucide 和项目现有 UI 组件。入口为 AdminLayout；总览、性能、用户、资源、配置、任务、日志使用 `/admin` 的 query tab，音乐库使用 `/admin/music`。角色路由守卫、Cookie session、CSRF 和请求客户端继续沿用现有实现。

主要问题是工作台玻璃样式造成过多视觉噪音，通用标题与业务标题重复，表格与配置字段缺少统一密度，用户和任务详情堆在列表下方，首次异步加载可能短暂显示空列表。音乐文件名与试听控件挤在同一行，标签以单字圆形叠放难以辨认，标签管理操作只在 hover 时出现，部分字段缺少可访问名称。

## 设计体系与公共组件

管理区独立使用 `src/styles/admin.css`，通过 `.admin-shell` 限定影响范围。浅色与深色使用语义 CSS 变量；中性不透明表面、低饱和蓝色操作色和一致的状态色替代玻璃、渐变和大面积阴影。间距为 4/8/12/16/20/24/32，圆角为 4/8/12；页面标题 24px、正文 13px、表格 12px、辅助文字 11/12px。保留焦点轮廓、150ms 颜色过渡和 reduced-motion 支持。

导航宽度 224px，按运行与监控、账户与资源、平台设置分组；主区域宽度上限 1600px，配置表单上限 1040px。页面标题、说明与主要操作统一在一行，避免额外的装饰性顶栏。

新增六个实际复用的后台组件：

- `AdminPageHeader`：统一页面名称、说明和操作。
- `AdminStatCard`：统一指标层级与缺失数据说明。
- `AdminTable`：语义表格、可聚焦的内部横向滚动区域。
- `AdminEmptyState`：紧凑、与场景对应的提示和恢复操作。
- `AdminLoadingState`：首次请求骨架和可访问加载提示。
- `AdminDrawer`：详情和复杂编辑；支持 Escape、Tab 焦点循环和关闭后焦点恢复。

按钮、输入、状态、确认框和 Toast 继续复用现有 UI 组件；管理区通过主题变量及限定样式统一外观，没有引入新依赖。

## 交互与业务边界

首次请求成功前不会把空数组解释为空业务数据；请求错误提供重试，刷新显示忙碌状态。管理页面增加请求序号保护，切换 tab 或离开缓存页面后旧响应不能覆盖新数据；自动刷新在操作或请求进行时暂停。管理操作开始时使先前读取失效，保存期间屏蔽外部刷新，操作自身仍能刷新结果；被中断的读取或保存期间的页面切换会在操作完成后恢复。用户筛选改变后重置分页，结果缩减时校正页码；异步管理操作防止重复执行。

原有 API、路由、角色守卫、数据结构、任务查询参数、配置提交、音乐上传/识别/匹配流程保持原有契约。最后一个启用管理员的保护以及危险操作确认仍保留。UI 重构没有迁移、任务注册表或状态存储改动。

### 统一功能开关

启用/停用设置统一使用现有 Switch 组件，管理区尺寸为 40×24px、圆点 20px；关闭采用中性灰，开启采用主题蓝，150ms 圆点位移与颜色变化表达状态。文本处理、解析、音频、GPU 调度、日志、注册及音乐启用采用相同视觉规则。标签关联、Space/Enter 操作、焦点轮廓、禁用及 reduced-motion 一并保留。曲目勾选属于选择操作，仍使用复选框。

“状态标签 + 开启/关闭按钮”占用空间且同时表达当前状态与反向操作，GPU 复选框则与同类启用设置不一致，因此合并为一套滑块。即时保存的日志与注册始终标注“即时保存”，保存时仅在圆点内显示加载动画并防重复点击；仅在服务器确认后切换状态，失败保留原状态及错误反馈。额度按钮仅响应自身保存状态。表单中的开关仍编辑草稿，由现有保存按钮提交，不改变设置生效时机。共享 Switch 新增可选 busy 支持，几何样式限定于管理区，用户工作台沿用原尺寸。

### 状态流量与表格修正

每日 API 请求统计排除健康、日志开关、管理监控及任务状态的 GET 检查，业务读请求与写操作仍计数。状态请求继续进入延迟、错误及性能采样，统计按当前进程与控制台时区日期计算，不回溯扣除旧计数。

用户、任务与日志表格贴合卡片边缘；固定操作列与整行共享悬停背景和过渡。资源分类、用户占用表格允许列内换行，避免小卡片内不必要的横向滚动；列较多的业务表格仍允许容器内滚动。

截图：[统一开关](admin-ui/toggles-general.png)、[资源表格](admin-ui/resources-tables.png)、[整行悬停](admin-ui/users-hover.png)。浏览器延迟 8 秒模拟保存时，两个即时开关保存前、中、后几何位置一致，未修改真实设置。

## 浏览器检查与二次优化

实际运行本地 API 和 Vite，遍历八个一级页面及六类配置，检查用户/任务详情、音乐编辑、确认框取消、键盘关闭与焦点恢复。真实音乐库为空，因此另用隔离只读 fixture 检查多曲目、长文件名、标签及深色主题；fixture 不修改用户设置或音乐数据。用户接口失败通过 fixture 注入并验证重试恢复。

第二轮 UX review 修复了 880px 全局布局断点与后台布局冲突、音乐抽屉被父级间距偏移、长文件名被播放器挤压、标签文字难以识别、资源表格过宽、配置数字框过宽及重复更新时间。加载、空态、错误态、禁用态、选中态和浅/深主题均进行了可视检查。正常页面检查未发现浏览器控制台错误或警告。

检查宽度包括 1440、1280、1024、768 和 390px。桌面保持左侧导航；窄屏使用可横向浏览的导航、单列内容和自适应操作区。复杂表格保留可读列宽，在表格内部滚动，操作列固定；390px 检查未发现整页横向溢出。临时 viewport 设置在验收后恢复。

## 验证结果

- `npm.cmd run build`：通过，包含 Vue/TypeScript 类型检查与生产构建。
- `npm.cmd run test:admin-console`：12 项通过，覆盖旧请求、停用缓存页面、加载失败、筛选排序、分页、重复操作、管理员保护、保存与刷新竞争、慢监控轮询及即时开关保存反馈与失败恢复。
- `npm.cmd run test:state-isolation`：15 项通过。
- `npm.cmd run test:gpu-scheduler`：7 项通过。
- 完整后端套件 `pytest backend/tests -n 4 --dist loadscope --basetemp <独立临时目录>`：1219 通过、5 跳过；新增状态请求排除与业务请求保留的回归验证。
- `git diff --check`：通过。

此次后端改动限于每日请求统计过滤与口径说明，完整后端测试已通过。浏览器验收没有实际执行删除、额度调整、角色变更或真实设置保存，避免改变本机业务数据；开关保存通过内存模拟接口验证，相关现有行为由自动回归和接口测试补充验证。

## 仍存在的限制

现有监控 API 为快照，未提供真实历史趋势，未添加虚构图表。TTS/LLM 用量及 GPU 指标在未采集时仍显示未采集；Worker 未运行时如实显示告警。任务与日志保留原有 API 返回数量范围，未把有限结果包装为全库分页。音乐 fixture 不提供真实音频文件，试听播放和真实 AI/合成任务未在此次视觉验收中端到端运行。
