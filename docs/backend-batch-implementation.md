## 已锁定的行为

- 全部 15 项属于目标，不延期或用更小范围替代。
- 停机统一升级，兼容旧工作空间与历史数据，不支持旧 Worker 并行写入。
- 重型混音预检由 Worker 执行；接口返回稳定批次回执，任务报告逐章错误。
- 保留任务独立取消、暂停、重试、租约 fencing、额度和可恢复成果发布。
- 批量操作每批最多 1000 个条目，前端顺序分批并保存原幂等键恢复回执。
- 以全量后端套件 `-n 4 --dist loadscope`、前端构建/相关回归、分层检查和隔离压力证据共同验收。

## 最终审核门禁

- 各阶段实现、迁移与旧数据兼容均有直接证据。
- 四机械 Worker、1000 个音频任务不突破全机许可数；进程退出未知时不回收许可。
- 合并边界停顿及音频样本一致性；多 GB ZIP 使用有界内存。
- BGM 单章读写、角色局部样本与定向失效，不重复处理整书。
- 1000 个任务批量提交的 SQL/事务/唤醒预算及幂等恢复。
- 文件碰撞、最新交付资格、部分结果、历史别名及删除/覆盖均保持正确。
- 持续轮询下进度重算不突破刷新间隔，时长缓存避免重复探测。
- 维护恢复不会遗漏后排失效租约，Redis 至少一次派发仍保持幂等。
- PostgreSQL、真实子进程和 Windows 验收范围逐项明确；缺失环境证据不宣称完成。
- 当前源码、测试结果、PR 状态与交付文件逐项重新检查后，才报告整个计划完成。

## BGM 按章状态验证与升级

- 存储/迁移/锁定引用/管理员统计/音频并发相关回归：224 passed。
- 新增同章四进程累计更新、迁移中断恢复、原 stem 碰撞、删除/损坏不回退旧数据、摘要发布版本及降级导出回归。
- 最终全量后端：1574 passed、23 skipped；`npm run build:all` 通过。
- `scripts/verify_bgm_state.py`：100/500/1000 章累计序列化分别 562,280 / 2,812,280 / 5,624,780 字节；单章读取始终两个文件、5220 字节。单章写入包含章状态、章摘要与小型发布版本元数据，开销不随全书大小增长。
- 上述测量在临时目录执行，无生产 journal 或 HTTP/数据库提交耗时，不能作为端到端吞吐承诺。

停机升级时，在数据库迁移后、API/Worker 重启前，对每个工作空间执行：

```bash
.venv/bin/python scripts/migrate_bgm_state.py <workspace>
```

迁移保留旧 JSON 和不可变快照。只读 API 不启动迁移；未迁移的旧工作空间仍可读取，第一次写入会在维护锁下完成迁移。完成标记出现后，读写不再使用旧 JSON。

降级导出：

```bash
.venv/bin/python scripts/migrate_bgm_state.py <workspace> --export-legacy <separate-export-directory>
```

导出不覆盖原始旧 JSON，不删除 v2 状态。降级仍须停止所有写入进程、备份数据库与整个工作空间，再使用已校验的导出替换旧格式；再次升级前须归档此前 v2 状态，防止旧完成标记屏蔽降级期间的编辑。直接恢复同一批数据库/工作空间备份也是回滚路径。

## 角色样本与定向失效：已提交证据

- 按章构建一次不可变 SQLite 剧本快照，角色任务按索引读取自己的台词和局部上下文；输入身份变化建立新的快照。
- Worker 不再为每个角色执行全角色两两关联；列表按角色简介、性别及台词数量的版本缓存关联提示，声音引用变化不重算提示。
- speaker→manifest 索引避免反复读取无关 manifest 的 JSON；损坏派生索引保留诊断副本并重建。
- 最后一次全量后端验证：1583 passed、23 skipped，42.57 秒；`npm run build:all` 通过（类型检查、构建、编译、分层契约）。
- 隔离样本准备测量：100/500/1000 个角色、40 章，均只构建一次快照、读取源章节 JSON 40 次；累计准备耗时约 0.25/1.22/2.45 秒，额外峰值 RSS 约 1.90/1.70/2.16 MiB。
- 上述测量不包含 LLM、数据库领取或最终成果发布，不能作为生产吞吐承诺。可用 `.venv/bin/python scripts/verify_role_snapshot.py` 在临时目录重跑。
- 未完成：相同批次的快照引用和输入版本绑定（阶段 5），旧入口逐角色遍历/检查源文件身份、声音失效逐次扫描 manifest 文件元数据，以及快照保留清理与外部编辑兜底（阶段 7）。目前不能宣称“单角色无全书准备扫描”或“声音变化只触及相关章节”的完整验收通过。

## 原子批次后端：当前实现与剩余工作

- 文本解析（新版及旧入口）、角色基础/克隆、BGM 分析/匹配/混音使用同一原子批次协议。配置在 TaskBatch 保存一次，任务及事件按 100 条分块写入，项目行锁覆盖冲突检查至整批提交；每批最多 1000 个目标。
- 一个非空批次只生成一个唤醒 Outbox 事件；保留任务独立领取、暂停、取消及重试。克隆仍保留共享执行批次语义。
- 客户端请求身份用于同键重放，服务端解析后的参数、配置及输入摘要另纳入批次哈希。回执在可变预检之前恢复；已接受后输入或配置变化、额度耗尽不会使同键重放创建新任务。不同项目/类型/参数复用同键返回冲突。
- 解析 Worker 从批次读取配置；执行前校验文件表和磁盘内容摘要，执行后再次校验，避免把旧解析结果标成新输入版本。LLM 暂停恢复探测同样使用批次原模型配置，不回退当前工作空间模型。
- 已测试 SQLite 并发同键及重叠目标、跨 BGM 类型冲突、第二块写入失败整批回滚、输入在解析中被替换、额度及失配处理。
- 隔离提交层 1000 条：BGM 匹配/混音各 26 条 SQL，BGM 分析及角色基础/克隆各 27 条，文本解析 28 条；均准备一次、commit 一次、唤醒一次。
- 实际文本解析 HTTP 路由 1000 章：已有文件表记录时 44 条 SQL；旧磁盘文件批量补登时 56 条 SQL；均一个 commit、一个唤醒。SQL 计数在建库、注册账号、设置额度和准备输入完成后开始，包含 HTTP 请求中的认证及业务语句。
- 测量使用隔离 SQLite 数据和临时工作空间，不代表 PostgreSQL/Windows 吞吐；角色和 BGM 的 HTTP 全路径预算仍须在版本绑定完成后复测。
- 本次后端提交最终全量回归：1602 passed、23 skipped，42.40 秒；`npm run build:all` 通过，随后最终改动再次编译检查通过。源文件在解析中变化、补登目录链接越过所属项目，以及补登记录随第二块任务插入故障回滚均有直接回归。
- **剩余项**：角色共享快照引用及输入版本绑定，BGM 章状态/音频输入版本绑定，前端原幂等键按账号/项目持久化、超过 1000 顺序分批及断线恢复，PostgreSQL 并发验收。第五阶段尚未完成。
