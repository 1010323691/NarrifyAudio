# 后端批量任务性能优化落地计划

基线：`17c4329`。目标：覆盖批量负载审计的全部 15 项问题，并处理 GPU 队列统计与重复维护扫描。

当前状态（2026-10-09）：阶段 1—5 已有本地提交，仍需补齐综合验收。阶段 6 已实现定向发布、当前交付索引、分块回填及维护迁移，仍待综合验收。阶段 7 的探测缓存、Outbox pipeline、全机维护协调与恢复分页已实现并验证，本轮补齐进度刷新节流、工作区受管写入版本（含派生索引失效与快照清理预算）和保留清理单轮预算，剩余持续轮询综合负载与 PostgreSQL/Windows 验收。阶段 8 已实现解析历史 SQL 窗口化、分册模块 SQL 过滤、保真骨架相等快速路径与 GPU 队列 SQL 聚合，有隔离验证与回归。角色/manifest 的逐任务全书源身份检查按输入变更完整性契约保留（依据见实施记录「本轮证据」）。各阶段实际证据与未完成项见 [实施与验收记录](backend-batch-implementation.md)。局部测试通过不等于阶段完成，更不等于整个计划完成。

## 目标与边界

- 支持数百至 1000 个任务排队，执行并发遵循整机资源预算。
- 去除每任务重复扫描整书、每文件重复加载历史、整包内存缓冲和逐任务提交事务。
- 保留独立取消、暂停、重试、租约 fencing、额度幂等、发布 journal 和输入身份验证。
- 采用停机统一升级，迁移兼容旧工作空间和历史数据，不允许旧 Worker 与新 Worker 同时写入。
- 重型混音预检由 Worker 执行；API 返回批次回执，逐章错误在任务中报告。
- 不修改模型推理语义、音频边界停顿、资源交付资格和文本忠实性判定。

## 分阶段实施

### 阶段 1：全机机械音频并发许可（审计项 1）

改动：在平台层持久化音频许可，将 `tts.merge`、`bgm.mix` 的领取与许可占用绑定到同一事务。全机上限为 `max(1, min(4, cpu_count // 2))`；FFmpeg 按全机预算分配线程。公平领取跳过当前无许可的音频任务，其他任务继续执行。

许可记录 Worker 与子进程身份。租约到期不能直接证明子进程已退出；退出未知时保留许可并暴露诊断。暂停先停止音频子进程，再释放许可；恢复必须重新取得许可。Windows 使用进程身份和 Job Object，Linux 使用受控进程组。

默认可用内存低于 2 GiB 停止新音频准入，达到 3 GiB 恢复；无法读取内存时仅允许一个任务。这是保守准入，不能替代阶段 2 的流式内存控制。

验收：4 个机械 Worker、1000 个排队任务，真实子进程数量不突破许可；覆盖暂停/恢复、取消、崩溃、过期租约、PID 重用和启动窗口故障。数据库迁移与许可回收均有测试。

### 阶段 2：流式音频合并与磁盘 ZIP（审计项 2、3）

改动：替换 TTS 两级合并中的 AudioSegment 列表和增长缓冲区，按现有格式同步规则逐块写出 PCM/WAV；保留 `boundary_gap_ms` 和跨分片停顿。超过 WAV 传统容量时使用 RF64。保持当前 MP3 编码器与参数。

`audio.zip`、`bgm.package` 直接写 attempt 暂存文件，启用 ZIP64；新增文件型成果构造函数，分块计算摘要，接入现有发布 journal、取消及失败清理。

验收：30 分钟以上音频，比较样本、总帧数、格式与全部边界停顿；2 GiB 和 8 GiB 归档额外 RSS 不超过 128 MiB。覆盖超过 4 GiB、取消、中断与发布恢复。

### 阶段 3：BGM 按章状态与轻量提交（审计项 6、7）

改动：在 `08_bgm/.state-v2/` 按章节存储分析、匹配和时间轴；文件名采用章节 stem 的摘要，内容保留原 stem、格式版本与输入版本。单章使用单章锁；总览只读取轻量摘要并分页。

旧全书 JSON 通过维护锁迁移，先建立不可变快照，再逐章写入，最后写迁移完成标记。未完成迁移可恢复；完成后停止旧格式回退读取，保留旧文件供备份恢复。

API 仅校验权限、参数与有界引用；Worker 加载本章状态、验证输入并执行重型音频预检。

验收：100/500/1000 章下，单章读写不随全书字节数增长；不同章并发不互相覆盖。同章冲突、迁移中断、旧数据和预检失败均保持正确行为。

### 阶段 4：角色样本快照与定向失效（审计项 4、5）

改动：由 Worker 懒构建一次不可变 SQLite 剧本快照，保存章节顺序、台词、角色索引和输入版本。相同批次角色任务共享快照引用。单角色读取自己的台词，按前/中/后采样并取得前后 4 条上下文；按章节构建，限制内存。

将全角色两两关联从每个角色任务中移出，改为按版本缓存的项目摘要。维护 speaker→章节索引，声音改变只处理相关 manifest；保留旧音频归档与旁白、BGM 下游失效。

验收：100/500/1000 个角色共享一次快照构建与一次关联摘要；单角色无全书准备扫描。已有合成结果后改一个声音，只触及相关章节；输入或声音版本改变使派生数据失效。

### 阶段 5：非 TTS 批量提交与幂等回执（审计项 10）

改动：文本解析、角色与 BGM 接入 TaskBatch；配置快照一次保存、按 100 条分块插入、单事务提交、单次队列唤醒。一个批次最多 1000 条，整批提交原子生效。

幂等内容包含项目、任务类型、引用、输入版本与参数；在同一原子检查中避免重复在途任务。返回保留 `task_ids`，新增 `batch_id`。Worker 验证输入版本。

前端超过上限时顺序分批；提交前保存原 Idempotency-Key，丢失响应后用原键取回回执。持久化状态按账号和项目隔离。兼容无键旧客户端，但不承诺其重放不重复。

验收：1000 条提交不超过 80 条业务 SQL、一个 commit、一次唤醒；统计口径不包含测试建库与迁移。覆盖并发同键、同键不同内容、响应丢失、部分插入异常、额度和重复在途冲突。

### 阶段 6：定向发布与当前交付索引（审计项 8、9）

改动：ProjectFile 增加规范化、大小写折叠的 object-key 索引，仅查询待发布目标。索引保存规范化路径的固定长度摘要，避免旧合法路径经 Unicode 展开后超过字段或 B-tree 大小限制；原路径保留。迁移分块回填，保留旧碰撞记录，不添加会导致历史数据迁移失败的唯一约束。普通成果采用 attempt 唯一名称；legacy 清理移到维护流程，仅退休已有有效平铺替代文件的旧项，保留旧格式独有数据。

新增 CurrentDelivery，以项目和相对路径标识当前交付资格，记录权威任务、文件身份、版本与有效/撤销状态。TaskResult 和索引事务一致；较新的不完整结果产生撤销标记。旧历史由 Worker 一次回填，完整后再切换读取。

单文件资格查询只读该路径，资源打包每文件仍重新验证最新资格与身份。

验收：覆盖 Windows 大小写碰撞、旧别名、重复制作、部分新结果、删除和替换，以及打包过程中资格撤销。项目文件数和历史轮数增加不能导致每个成果再次加载全部目录或历史。

### 阶段 7：刷新节流、探测缓存与维护协调（审计项 11、12、13）

改动：制作进度改用成果版本与 dirty 状态，纯任务进度不触发全书重算。同项目最多一个刷新任务，启动间隔至少 30 秒；运行期间再次变脏安排尾随刷新，外部文件编辑保留 5 分钟兜底。

建立持久化 SQLite ffprobe 缓存，键包含文件身份、探测工具身份与参数；探测前后校验身份，仅缓存成功结果，供时间轴、混音和预览共享。

全机一个维护协调者：恢复每 10 秒扫描一次、每批 100 条，SQL 过滤真正失效租约并使用游标避免饥饿；Outbox 每批 100 条通过 Redis pipeline 发送，成功项一次提交，保留至少一次投递与幂等消费。资源保留清理也归协调者。

验收：持续轮询 30 分钟满足最小刷新间隔并最终更新；第二轮未变音频不再启动探测进程；活跃任务不会挡住后排失效任务；Redis 部分失败和协调者退出不丢任务、不重复业务执行。

### 阶段 8：历史摘要与算法收尾（审计项 14、15及 GPU 统计）

改动：SQL 窗口函数按规范输入身份选择最新解析任务和最新成功任务，仅加载所需结果；split 模块在 SQL 中过滤。保留原始名、清洗名及旧无指纹结果兼容。

忠实性检查增加骨架完全相等快速路径，其余继续使用 `autojunk=False` 和原判定规则。GPU 队列统计改为 SQL 聚合，对合格任务与 GPURequest 去重，保留最早排队时间语义。

验收：1000 章、每章 20 轮历史下，每章只物化需要的任务与结果；旧结果状态正确。重复文本快速返回，非相等文本检测结果不变。GPU 重复请求、失效请求和不合格任务统计正确。

## 实施顺序与交付

顺序为 1→2→3→4→5→6→7→8。阶段 3 为 BGM 批次提供按章版本，阶段 4 为角色批次提供共享快照；阶段 6 完成后，阶段 7 可用交付版本替代任务更新时间。

## 测试与升级

每阶段运行相关回归，后端变更完成后运行完整 `pytest backend/tests -n 4 --dist loadscope`。依赖变更执行导入分层门禁；共享前端流程执行 typecheck/build 和相关工作台、状态隔离回归。

升级：备份数据库与工作空间→暂停新提交并排空或安全暂停任务→停止 API/Worker→数据库与工作空间迁移→验证迁移完成标记→统一启动新版本→冒烟与积压任务验收。

回滚：停止全部写入进程；恢复数据库和工作空间同一批备份，或先执行已验证的 BGM 旧格式导出再降级。未确认子进程退出不得释放音频许可；不得让旧 Worker 读取新格式并写回。
