## 问题与约束

角色配音页三个子窗口（picker/merge/confirm）打开时背景页未设 `inert`（仅嵌套确认对 merge 面板用 `:inert="mergeConfirm || undefined"`）。审核 [P3]（仅供参考级）指出：请求在途（overlay 零可用控件）时 Tab 进入背景后可 Enter 激活背景控件。

## 决定与原因

本 PR 不修复，记为后续独立 a11y 项：「子窗口打开时给背景整体设 `inert`」。原因（再裁决逐条核实成立）：
1. 非本次修复引入的回归：背景未 inert 是 PR 既有设计；鼠标路径已被 backdrop（`fixed inset-0`）全拦截，暴露面仅键盘用户；修复前 body 上的 Tab 本就可经原生路径逸出页根 handler。
2. 实际暴露面比原描述更窄：行级变更入口（选择音色/合并/性别/重新制作等）位于 `VoicesWorkbench.vue` 的 `:inert="overlayOpen"` 详情面板内（:155/:160/:170/:178），不可达；可达面仅剩本地 UI 态与受 busy 门/请求序号守卫的阶段操作，无数据面风险。
3. 根因修复需回归三个 overlay 与嵌套确认的焦点归还路径（`inert` 可直接绑定现有直接子级：VoicesWorkbench 根 / `.voices-production` / `.voices-footer`，无需包裹容器、不破坏 flex 直接子级契约），工作量与独立验证需求超出一个仅供参考项的比例。

## 替代方案与影响

- 本 PR 内修复（拆独立项未采用）：见上第 3 条。
- 保留 [P2] 修复前的「在途 Tab 冻结」行为（未采用）：会复发 [P2] 症状（键盘导航临时失效）。
- 影响：未来做该 a11y 项时，须处理 inert 与 `overlayReturnFocus`/`confirmReturnFocus` 焦点归还、嵌套确认（confirm 覆盖 merge）的交互；本决策不改变现网行为。
